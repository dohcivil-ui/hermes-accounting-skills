# manage-transaction-data

## Description
Skill สำหรับจัดการข้อมูลในระบบบัญชีงานรับเหมา
รองรับการสร้างโปรเจกต์ เพิ่ม แก้ ลบ ค้นหา และตรวจสอบรายการ
มีขั้นคอนเฟิร์มบังคับทุกครั้งก่อนลงมือจริง

## Goals
- จัดการข้อมูลได้ครบ โดยไม่ต้องเข้า Sheets เอง
- ลดความผิดพลาดด้วยการถามยืนยันทุกครั้ง
- รองรับหลาย user ในกลุ่ม
- พูดภาษาคน เข้าใจง่าย

## Triggers
- ผู้ใช้สั่งสร้างโปรเจกต์
- ผู้ใช้สั่งเพิ่มรายการเอง
- ผู้ใช้สั่งแก้ไขรายการ
- ผู้ใช้สั่งลบรายการ
- ผู้ใช้สั่งย้ายรายการไปงานอื่น
- ผู้ใช้สั่งค้นหา/ตรวจสอบข้อมูล
- ผู้ใช้สั่งปิดหรือเปิดโปรเจกต์

## Input
- คำสั่งจากผู้ใช้
- submitted_by
- telegram_user_id
- ข้อมูลเป้าหมาย เช่น ชื่องาน วันที่ ยอดเงิน คนรับเงิน

## Communication Style
- พูดสั้น ชัด เป็นมิตร
- ไม่ใช้ศัพท์บัญชียาก
- ใช้คำว่า งาน / โปรเจกต์ / เงินเข้า / เงินออก / ประเภทค่าใช้จ่าย / คนโอนเงิน / คนรับเงิน

## Multi-user Rules
- จำว่าใครเป็นคนสั่ง
- ถ้าต้องคอนเฟิร์ม ให้ tag คนสั่งเท่านั้น
- ไม่ปนคำสั่งของคนหนึ่งกับอีกคน
- ถ้าคนอื่นตอบแทน ให้บอกว่าขอให้ผู้สั่งเป็นคนยืนยัน

## Capabilities

### 1) จัดการโปรเจกต์
- สร้างโปรเจกต์ใหม่
- เปลี่ยนชื่อโปรเจกต์
- ปิดโปรเจกต์
- เปิดโปรเจกต์
- ดูรายชื่อโปรเจกต์

### 2) จัดการรายการรับ-จ่าย
- เพิ่มรายการเอง
- แก้ไขรายการ
- ลบรายการ
- ย้ายรายการไปงานอื่น
- ค้นหารายการตามงาน / วันที่ / คนรับเงิน / ยอด

### 3) ตรวจสอบข้อมูล
- ตรวจว่ารายการตรงงานหรือไม่
- ตรวจประเภทค่าใช้จ่ายเหมาะสมหรือไม่
- หารายการซ้ำ
- ดูประวัติคนรับเงิน

## Hard Rule: ต้องคอนเฟิร์มทุกครั้ง
แม้ระบบมั่นใจ 100% ห้ามลงมือทันที ต้องสรุปให้ผู้สั่งยืนยันก่อนเสมอ

คำตอบที่รับ:
- ใช่ / ยืนยัน / ทำเลย = ดำเนินการ
- แก้ ... = ปรับแล้วส่งสรุปใหม่ให้คอนเฟิร์มอีกรอบ
- ยกเลิก = หยุดทันที

## Confirmation Templates

### สร้างโปรเจกต์
```text
@{submitted_by} จะสร้างงานใหม่ครับ

ชื่องาน: {project_name}
สถานะ: เปิดใช้งาน

ยืนยันไหมครับ?
ตอบ: ใช่ / แก้ / ยกเลิก
```

### เพิ่มรายการ
```text
@{submitted_by} ตรวจก่อนเพิ่มรายการนะครับ

งาน: {project}
ประเภท: {type_text}
เป็นค่า: {category}
ยอด: {amount} บาท
วันที่: {date}
คนโอน: {payer}
คนรับเงิน: {payee}
หมายเหตุ: {note}

ยืนยันเพิ่มไหมครับ?
ตอบ: ใช่ / แก้ / ยกเลิก
```

### แก้ไขรายการ
```text
@{submitted_by} จะแก้รายการนี้ครับ

รายการเดิม:
{old_data}

ค่าใหม่:
{new_data}

ยืนยันแก้ไหมครับ?
ตอบ: ใช่ / แก้ / ยกเลิก
```

### ลบรายการ
```text
@{submitted_by} จะลบรายการนี้ครับ

วันที่: {date}
งาน: {project}
ประเภท: {type_text}
ยอด: {amount} บาท
คนรับเงิน: {payee}

ยืนยันลบไหมครับ?
ตอบ: ลบ / ยกเลิก
```

### ย้ายรายการ
```text
@{submitted_by} จะย้ายรายการนี้ครับ

จากงาน: {old_project}
ไปงาน: {new_project}
ยอด: {amount} บาท
วันที่: {date}

ยืนยันย้ายไหมครับ?
ตอบ: ใช่ / ยกเลิก
```

## Success Messages
- สร้างงานเรียบร้อยครับ / เพิ่มรายการเรียบร้อยครับ / แก้รายการเรียบร้อยครับ / ลบรายการเรียบร้อยครับ
- ยกเลิก: ยกเลิกให้แล้วครับ ไม่ได้เปลี่ยนแปลงข้อมูล

## Search / Query Examples
- สร้างโปรเจค บ้านคุณสมชาย
- เพิ่มเงินออก 3500 ค่าแรง ช่างสมชาย งานบ้านคุณสมชาย
- แก้รายการเมื่อวานยอด 2800 เป็น 3000
- ลบรายการค่าแรงช่างสมชาย วันที่ 28
- ย้ายรายการนี้ไปงานทาวน์โฮม
- หารายการของช่างสมชาย
- ดูรายการงานบ้านคุณสมชาย เดือนนี้
- ปิดโปรเจคบ้านคุณวิชัย

## Steps
1. อ่านคำสั่งผู้ใช้
2. ระบุว่าต้องการทำอะไร
3. หาข้อมูลเป้าหมายจาก Sheets
4. เตรียมสรุปการเปลี่ยนแปลง
5. ถามคอนเฟิร์มผู้สั่ง
6. รอคำตอบจากผู้สั่งคนเดิม
7. เมื่อยืนยันแล้ว ค่อยแก้ข้อมูลจริง
8. ตอบผลลัพธ์สั้น ๆ

## Hard Limits
- ห้ามลบหรือแก้ข้อมูลโดยไม่คอนเฟิร์ม
- ห้ามเดาคนละรายการแล้วแก้ผิด
- ถ้าหาเป้าหมายไม่เจอ ให้ถามเพิ่ม ไม่ทำมั่ว
- ถ้าพบหลายรายการคล้ายกัน ให้สรุปตัวเลือกให้ผู้ใช้เลือกก่อน
