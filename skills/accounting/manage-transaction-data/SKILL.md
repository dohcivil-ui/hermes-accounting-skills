# manage-transaction-data

ใช้เมื่อมีคำสั่งจัดการข้อมูล: สร้างงาน / เพิ่ม / แก้ / ลบ / ย้าย / ค้นหา

## คำสั่งที่รองรับ

| คำสั่ง | ตัวอย่าง |
|--------|---------|
| สร้างงาน | "สร้างงานใหม่ชื่อ บ้านคุณสมชาย" |
| เพิ่มรายการ | "เพิ่มค่าแรง 5000 บาท งาน A" |
| แก้ไขรายการ | "แก้รายการ #12 เป็น 6000 บาท" |
| ลบรายการ | "ลบรายการ #12" |
| ย้ายรายการ | "ย้ายรายการ #12 ไปงาน B" |
| ค้นหา | "หารายการค่าแรงเดือนนี้งาน A" |

## ขั้นตอนทุกคำสั่ง

### 1. ตีความคำสั่ง
- ดูว่าต้องการทำอะไร (สร้าง/เพิ่ม/แก้/ลบ/ย้าย/ค้นหา)
- ดึงพารามิเตอร์ที่จำเป็น
- ถ้าขาดข้อมูล → ถามก่อน

### 2. แสดงสรุปสิ่งที่จะทำ + ถามคอนเฟิร์ม
```
🔧 สิ่งที่จะทำ:
[อธิบายสั้นๆ ว่าจะทำอะไร]

ยืนยันไหมครับ? (ใช่ / ยกเลิก)
```

> ⚠️ ห้ามลงมือก่อนได้ "ใช่"

### 3. ดำเนินการตามคำสั่ง

#### สร้างงาน (Projects sheet)
```
project_id: auto-generate (P-YYYYMMDD-XXX)
project_name: ตามที่ระบุ
customer: ถามถ้าไม่มี
status: active
start_date: วันนี้
created_by: username ผู้สั่ง
created_at: เวลาปัจจุบัน
```

#### เพิ่มรายการ (Transactions sheet)
กรอกครบทุก field เหมือน process-slip-pipeline ข้อ 6
แต่ `slip_url` = "-" และ `confidence` = 1.0 (manual entry)

#### แก้ไขรายการ
- ดึงรายการ #id จาก Sheets
- แสดงค่าเก่า vs ค่าใหม่
- อัปเดต `updated_at` = เวลาปัจจุบัน

#### ลบรายการ
- ไม่ลบจริง — เปลี่ยน `status` = "deleted"
- บันทึก `note` ว่าใครลบเมื่อไหร่

#### ย้ายรายการ
- อัปเดต `project` field
- อัปเดต `updated_at`

#### ค้นหา
- Query Sheets ตาม filter ที่ระบุ
- แสดงผลเป็นตาราง ไม่เกิน 20 รายการต่อครั้ง

### 4. แจ้งผล
```
✅ เสร็จแล้วครับ!
[สรุปสิ่งที่ทำ]
```

## กฎสำคัญ
- ถามคอนเฟิร์มทุกครั้ง ก่อนทุกคำสั่งที่เขียนข้อมูล
- ลบจริงไม่ได้ — ใช้ soft delete เท่านั้น
- บันทึกว่าใครสั่ง (submitted_by) ทุกครั้ง
